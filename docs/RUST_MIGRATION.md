# C++ 版から Rust 版への移行記録

確認日：2026-10-17。

この文書は、ちびスタックちゃんを Arduino C++ 版から現在の Rust アプリケーションへ移した経緯と、実機で確認できた範囲を記録します。現在のビルド・設定方法は [Rust ファームウェアの README](../rust/firmware/README.md)、顔描画の仕様は [Avatar 顔描画ライブラリの README](../rust/avatar-face/README.md) を参照してください。

## 出発点と履歴の保全

出発点は [atatakeisi/chibi-stackchan の C++ 版](https://github.com/atatakeisi/chibi-stackchan/tree/10460b3) です。確認時の先頭コミットは `10460b3` でした。元の C++ 版は別のチェックアウトにも残っていることを確認しています。

Rust 側の既存履歴では、[移行前の混在版の基準コミット](https://github.com/atatakeisi/chibi-stackchan-rust/tree/defdb3cc18ff25c809f529f237c8bd5cbbdc50ec) が `defdb3cc18ff25c809f529f237c8bd5cbbdc50ec` です。この段階では、Arduino C++ のアプリケーションへ小さな Rust 音声解析ライブラリをリンクしていました。

その後の作業では、録音・再生・画面・会話・設定・ネットワークを含むアプリケーション全体を Rust へ移しました。古い混在版と、現在の Rust 版の実測結果を区別するため、従来の記録は [RUST_INTEGRATION.md](../RUST_INTEGRATION.md) にも残しています。

旧ファイルの整理に先立ち、動作する作業状態を [整理前のチェックポイント `ffb5c74706a106e09211d558a028f2fccbaac537`](https://github.com/atatakeisi/chibi-stackchan-rust/tree/ffb5c74706a106e09211d558a028f2fccbaac537) として保存しました。親コミットは上記の `defdb3cc18ff25c809f529f237c8bd5cbbdc50ec` です。チェックポイントには旧 C++ / Rust 混在版と新しい Rust 版の両方が含まれます。元の C++ リポジトリだけでは、途中で追加した C ABI ブリッジなどの変更まで保存できているとは限らないため、このチェックポイントと元リポジトリを別に扱います。

## 移行の段階

### 1. 音声解析だけを Rust にした混在版

最初の `rust/audio-core/` は、録音済み PCM のピーク、100 ms ごとのピーク、音声区間数を解析する `no_std` ライブラリでした。C++ の `RustAudioCore.h` と C ABI で接続し、PlatformIO の `scripts/build_rust.py` で静的ライブラリをビルドしていました。

この段階では、本体制御・画面・通信・会話・設定保存は C++ のままでした。音声解析のホストテスト 2 件の成功は、この混在版に対する記録です。現在の Rust ファームウェアはこのライブラリへ依存していません。

### 2. アプリケーション全体を Rust へ移行

`rust/firmware/` を独立した Cargo プロジェクトとして作成しました。Arduino、M5Unified、ESP8266Audio をアプリケーションの実行時にリンクする構成から、Rust の `esp-idf-svc` / `esp-idf-hal` を通じてハードウェアと ESP-IDF を利用する構成へ移しました。

ESP-IDF 自体は C の SDK です。Rust 化したのはこのプロジェクトのアプリケーションとドライバーの実装であり、SDK まで全て Rust に置き換えたという意味ではありません。ESP-IDF のビルド生成物や SDK の C ソースは、削除対象の旧 C++ アプリケーションとは区別します。

| 旧 C++ / 混在版の役割 | 現在の実装 | 移行内容 |
|---|---|---|
| `src/main.cpp` の起動・状態管理 | `rust/firmware/src/main.rs`、`device.rs` | 初期化、録音・会話・再生、ボタン、待機・睡眠の制御 |
| `main.cpp` の呼びかけ・会話・タイマー | `conversation.rs` | 呼びかけ判定、履歴、表情、ローカルタイマー、AI 操作タグ |
| `main.cpp` の設定・Web UI | `config.rs`、`storage.rs`、`web.rs` | 入力検証、NVS 保存、設定画面、操作キュー |
| `Whisper` / `AudioWhisper` | `audio.rs`、`services.rs` | 録音、VAD、WAV 化、Whisper への送信 |
| `WebVoiceVoxTTS` / HTTPS 音声取得 | `services.rs` | VOICEVOX、会話 AI、天気の HTTPS 通信 |
| `AudioOutputM5Speaker` / ESP8266Audio | `board.rs`、`playback.rs` | ES8311、I2S、Symphonia による MP3 デコード、音量適用、リサンプリング |
| Web からの音量変更と、移行後に追加した音声操作 | `voice_volume.rs`、`voice_action.rs`、`playback.rs` | 定型命令の解析、AI 操作タグの検証、実出力と保存値の共有 |
| `HeadServo` | `board.rs` | PWM、首の位置・動き・待機時の制御 |
| `WeatherClock` と Wi-Fi 制御 | `network.rs`、`services.rs` | Wi-Fi、設定 AP、DNS、mDNS、時刻同期、設定地点の天気 |
| M5Stack-Avatar による顔 | `rust/avatar-face/`、`display.rs` | 独立した顔描画と、LCD 識別・初期化・画面転送 |
| `include/secrets.h` の初期値 | `storage.rs`、Web 設定 | 既存 NVS からの移行と設定画面を利用。Rust 版は `secrets.h` を読み込まない |
| `rust/audio-core/` の解析 | `rust/firmware/src/audio.rs` | 現在の録音・解析へ統合。旧 C ABI ライブラリは不要 |
| `platformio.ini` / `build_rust.py` | `scripts/firmware.py`、Cargo | 現行 2 クレートのテストと ESP32-S3 向けビルド |

現在のローカルの Cargo 依存は `rust/firmware/` から `rust/avatar-face/` への参照です。旧 `src/`、`include/`、PlatformIO、`rust/audio-core/` は、このビルドの依存に含まれません。

### 3. 元の顔を独立ライブラリとして復元

初期の Rust 版では顔を独自の描画へ変えたため、元の見た目と異なっていました。M5Stack-Avatar 0.10.0 の顔・目・口を基に、白い小さな丸目、四角い口、表情ごとの形、元の縮尺・配置を `rust/avatar-face/` へ移植しました。

顔の形状と、まばたき・視線・呼吸・傾きのアニメーションは LCD 制御から分離しました。ファームウェアの `display.rs` は、その結果を画面へ転送します。顔ライブラリには ESP-IDF の依存がなく、ホストで描画結果を検証できます。ユーザーが実機を見て「元の顔に戻った」と確認しました。

### 4. 実機の音と音量操作を修正

書き込み後の確認では、ビルドや設定値の読み戻しだけでは分からない問題も見つかりました。修正と確認の関係は次のとおりです。

| 症状 | 分かった原因 | 修正・確認 |
|---|---|---|
| 初回 MP3 デコード付近で停止 | Symphonia の遅延初期化が約 32 KiB のスタックを必要とし、メインタスクの 24 KiB を超えていた | メインタスクを 64 KiB に変更。再生完了、マイク復帰、待機状態を確認 |
| 音量を小さく設定しても大きすぎる | ES8311 の DAC レジスター `0x32` が `0xff`、+32 dB になっていた | `0xbf`、0 dB へ修正して読み戻しを確認。PCM 側の音量減衰と併用し、音量 0 ではアンプも停止 |
| 顔を戻した後、声がガラガラする | 顔描画とポーリング方式の LCD 転送が PCM の供給を遅らせていた | 顔のある範囲に描画計算を絞り、SPI のポーリングを無効化。512 通りの比較で画素の一致を検証し、ユーザーも自然な声へ戻ったと確認 |
| 「変更した」と返事しても、音量が変わったと確認できない | 音量命令が通常の AI 会話へ流れる場合があった | 定型命令を本体で解析し、保存・実出力への反映後に確認応答を生成。Web と音声で同じ音量制御を利用 |
| 呼びかけ付き・丁寧な音量命令が認識されにくい | 呼びかけの残存、読点、仮名表記、語尾などが厳密な命令解析に合わなかった | 設定した呼びかけと定型の前置き・語尾を処理。定型外の依頼では AI の操作タグを現在の依頼と照合してから適用 |
| 声で「音量20にして」と指定しても通常会話になる | 実際の文字起こしで「二十」が「二重」になっていた | 音量の数値部分が完全に「二重」の場合だけ 20 として扱う。「二重人格」や一般会話の本文は置換しない |

音量は iPhone の設定画面と同じ **0〜255** の値です。「20」は 20% ではありません。割合を指定する場合は「20パーセント」と明示します。消音前の 0 以外の音量も保存し、「ミュート解除」で戻します。ミュート中も音声入力は動作します。

音量命令は引用・否定・範囲外の数値・複数命令をそのまま設定変更に使わないよう検証しています。AI が返答したという理由だけでは、設定を変更したことにしません。

音量診断の `/status` は保存値・適用値・再生済み PCM の数値情報だけを返します。認識の切り分けに使う文字情報は、音量関連の USB ローカルログで長さを制限して扱い、Web へ文字起こしを返す機能や録音の保存は設けていません。

## ビルドと、設定を保った実機書き込み

リポジトリのルートで次を実行します。必要なツールチェーンや依存の準備は [ファームウェアの README](../rust/firmware/README.md) を参照してください。

```sh
python3 scripts/firmware.py test
python3 scripts/firmware.py build
```

現行版は ESP32-S3 向けの `xtensa-esp32s3-espidf` ターゲットでビルドし、アプリケーションの `.bin` を生成します。これらのコマンドは実機への書き込みを自動では実行しません。PlatformIO は不要です。

実機移行時は、最初に 8 MiB のフラッシュ全体を非公開のバックアップへ保存しました。実機のパーティション配置と生成した表が一致し、起動対象が app0 であることを確認したうえで、**app0 の `0x10000` にアプリケーションだけを書き込み**、書き込みハッシュの検証を行いました。app0 の容量は `0x330000` です。

ブートローダー、パーティションテーブル、NVS、SPIFFS は保持しました。Rust 版は旧 NVS の設定や SPIFFS のロール・キャッシュを読み込めるため、既存の設定を移行できました。フラッシュ全体の消去やパーティションの変更を、通常のアプリケーション更新と同じ操作として扱わないことが重要です。

実機バックアップには認証情報が含まれるため公開しません。また、フラッシュのバックアップはアプリケーションのソース履歴の代わりにはならないため、ソースは Git のチェックポイントで別に保全します。

## 旧ファイルの整理方針

整理前の作業状態をGitHubの固定チェックポイントへ保存した後、ユーザーの明示的な承認を受けて以下を削除しました。旧コードはチェックポイントと元リポジトリから参照できます。

| 削除したもの | 理由 |
|---|---|
| 旧 `src/`、`include/` | C++ 版のアプリケーション・ヘッダー・設定テンプレートで、現在の Rust ビルドから参照されない |
| `platformio.ini`、`scripts/build_rust.py` | C++ 版・混在版専用のビルド構成 |
| `rust/audio-core/` | 混在版専用の旧 Rust ライブラリ。現在の録音・解析はファームウェアに実装済み |
| PlatformIO の生成物・専用 IDE 設定 | 現行の Cargo ビルドでは使わない |

現在使用している `rust/firmware/` と `rust/avatar-face/` のRustコードは、整理前のチェックポイントから変更していません。`scripts/firmware.py`、マニュアル、画像、移行記録と、ドキュメント生成用ツールは保持します。旧ビルドの手順は現行の操作方法と区別し、整理前の Git 履歴や元リポジトリへたどれるようにします。
